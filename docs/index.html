Why it matters

不是再做一个聊天框，
而是让 Agent 处理运维任务

平台从 Java 服务异常出发，先形成事件与证据上下文，再按场景装配 Agent；运行状态和工具治理用于保证分析过程可靠落地。

传统 Java 运维的常见问题

  • 服务异常依赖人工发现和切换多个平台
  • 日志、指标、Trace 与知识文档彼此割裂
  • 不同服务重复开发独立分析流程
  • 模型结论缺少证据链和执行边界

平台提供的监督闭环

  • 主动探测、失败抑制与事件去重
  • 日志 / 监控 Skills 与动态 Agent 装配
  • RAG 知识增强与受治理 MCP 工具
  • Run 状态、恢复、SSE 与审计

Core capabilities

一套完整的 Java 智能运维闭环

从服务监督到证据检索，再到 Agent 分析、处置建议和恢复确认，每个环节都保留明确的工程语义。

01

Java 服务主动监督

探测 Actuator 健康端点，通过超时、慢响应和连续失败阈值减少抖动告警，并自动识别恢复。

02

事件聚合与去重

按服务维护活跃事件，累计异常次数和最近证据，支持确认、人工关闭与恢复自动关闭。

03

动态 Agent 装配

按场景组合 Model、Prompt、Advisor、RAG、Skills 和 MCP，共用 Auto、Flow、Fixed 执行引擎。

04

工具权限治理

执行前经过白名单、风险、授权、预算、幂等和熔断判断，降低模型误调用带来的副作用。

05

事件与评估

SSE 事件携带严格递增的序号、runId 与 traceId，并支持查询检查点、评估和审计记录。

06

双工作台

在 React 管理台查看服务快照与事件，一键触发分析；再通过 Agent 运行台查看 SSE 时间线和治理结果。

Operations flow

一次异常，
五个闭环阶段

从主动发现到恢复关闭，不依赖用户先知道应该问 Agent 什么。

查看监督设计

  1. 主动探测服务

    按目标配置探测 Actuator，记录状态、HTTP 响应、延迟与安全截断后的证据。

  2. 抑制抖动并聚合事件

    连续失败达到阈值才创建事件，同一服务的重复异常累积到已有活跃事件。

  3. 构建 Agent 分析上下文

    固定事实、环境、事件级别与探测证据，并路由日志和监控 Skills。

  4. 检索证据与受控执行

    Agent 通过 MCP 查询指标、日志和 Trace，所有调用经过白名单、风险、预算和审计。

  5. 输出结论并确认恢复

    返回影响范围、根因、止损与验证步骤；服务恢复 UP 后自动关闭对应事件。

Engineering honesty

明确写出边界

一个可信的作品集项目，不应该把演示实现包装成已经完成的生产系统。

  • 当前 Run、监督快照、事件和检查点使用有界内存实现。
  • 生产持久化 SQL 已设计，Repository 接入仍在 Roadmap。
  • 企业环境还需补充 RBAC、审批票据与分布式状态协调。
  • 工具能力依赖实际 MCP 服务，Skill 只定义调用边界。
