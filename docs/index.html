01 / Architecture

两个控制面，约束一次运行。

Run 控制面管理身份、状态、事件与恢复；Tool 控制面管理模型能否以及如何调用外部能力。 模型负责生成候选决策，应用代码负责合法状态转换和副作用授权。

Interface

React 运行台

启动、恢复、取消 Run，展示 SSE 时间线、评估和工具审计。

Protocol

HTTP / SSE

统一返回 runId、traceId、sequence 和运行状态。

Control plane

Run Runtime

状态机、幂等、检查点、恢复、取消与质量评估。

Routing

Skill Registry

文件型能力声明、校验、版本与可解释路由。

Execution

Auto · Flow · Fixed

保留三类执行策略，并把结构化决策、恢复上下文和运行事件注入统一生命周期。

Safety boundary

Governed Tool Callback → MCP

调用前执行 Skill 白名单、风险分级、人工授权、预算、幂等、重试与熔断；调用后写入脱敏审计。

02 / File-based Skills

场景方法论，不再写死在节点里。

每个 Skill 在 SKILL.md 中声明触发词、场景、允许工具、风险和优先级。 新增场景无需修改执行引擎，工具集合默认最小化。

S-01 · READ ONLY

日志根因分析

围绕时间窗、TraceId、错误码和异常堆栈形成证据链。

S-02 · READ ONLY

监控指标诊断

关联错误率、延迟、吞吐和资源曲线，定位异常拐点。

S-03 · GROUNDED

知识证据问答

先检索可信依据，再组织带来源边界的回答。

S-04 · CONTROLLED

故障应急响应

按影响、止损、定位、恢复和复盘组织线上处置。

S-05 · CHECKLIST

发布巡检

覆盖发布前基线与发布后健康度、日志和回滚条件。

S-06 · READ ONLY

SQL 性能诊断

从执行计划、索引、锁等待和数据分布解释性能瓶颈。

03 / Event trace

每一步发生了什么，都能回放。

04 / Tool governance

Prompt 是建议，代码才是边界。

工具治理位于真实 ToolCallback 外层。即使模型被提示注入或忽略规则，副作用仍必须经过应用侧的 fail-closed 校验。

最小权限

工具名必须命中当前 Skills 合并后的 allowlist；无 Skill 命中时默认不开放工具。

预算与幂等

限制单次 Run 的工具调用总量，并用 runId、工具名和输入摘要避免重复副作用。

高风险授权

写入、删除、发布、回滚等操作必须具备可信授权；本地请求字段只用于演示。

审计与韧性

记录脱敏输入、决策、耗时、重试和错误；只读调用支持有限重试与熔断保护。
